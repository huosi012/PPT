# 踩过的坑（以及为什么）

## 渲染与环境
- 沙盒的 LibreOffice 往往只有 core，`soffice --convert-to pdf` 报 “source file could not be loaded”——装 `libreoffice-writer`。没有 `pdftoppm` 就装 `poppler-utils`；中文字体装 `fonts-noto-cjk`。
- 预览字体是替代字体，Word 里是真微软雅黑：**行高会不同**。所以新写的文字全部用“固定值”行距，否则 Word 里分页和预览对不上（用户截图发现第 2 页被挤掉一行、页底空一截）。
- 原文档普遍开着“对齐文档网格”（docGrid linePitch），LibreOffice 会把行距撑到两倍网格——段落要设 `snapToGrid=0`。

## XML 细节
- pPr/rPr/tcPr/tcBorders 子元素有 schema 顺序，乱序 Word 会报损坏——用 `docx_kit.put()` 按序插入。
- `keepNext` 放在表格单元格段落里，Word/LO 会把**整行**和下一行绑定，导致整块内容被推到下一页；卡片标题不要加 keepNext。只在“分区标题栏 / 阶段行 / 表头行”上用，让它们跟随下一行。
- 单元格必须以段落结尾：嵌套表后面要留一个段落，用 1 磅高的空段（`line=20` 固定值）避免视觉空隙。
- run 级底色做标签时，首尾空格的底色在 LO 里会错位——用同色 `w:bdr` 撑内边距，不要用空格。
- 表格 `tblCellSpacing` 在 LO 里不显示；卡片间距用白色粗边框或共用细线。
- 自动编号（numPr）和手写编号混用会出现“1. 1.”或序号错位（原文就有“1、2、2”）。改写前先渲染确认自动编号实际显示的数字，再统一成手写金色编号并去掉 numPr。
- 文本里的浮动图（wp:anchor）的 `posOffset` 数字会被 `itertext()` 读成正文（如“1562103164840类似性”）——取文字只读 `w:t`。
- 单元格里除了段落还可能有**嵌套表**（用户换图时常放在单格小表里）：重排段落时要按原顺序保留所有子元素，否则嵌套表会跑到格子顶部。

## 版式判断
- 用户反感：大色块、颜色太多、“草稿感”（空格子、左栏大片空白、卡片高度不齐、字太小）、“表中表”缝隙、页底大片空白、边框颜色不统一。
- 空值填“待填写”（浅灰），比空格子更像成品。
- 同一信息多处出现时只在一处高亮（例：三等规律只在“教学重点”用标签）。
- 合并硬换行：上一段不以句读结尾、长度 > 12、且上一段不是标题/编号项时才合并——否则会把“四、…”标题和下一段正文并成一个粗体大段、把“（4）…”和下一句并在一起。
- 两端对齐在窄栏里会把中文字距拉开，窄栏用左对齐。

## 填满页面
1. 所有新写文字固定行距；每行 `cantSplit`（超长行如“示范讲解”例外，允许跨页）。
2. 为每一页定义“这一页应当以哪一行结束”，给该页各行的内容格上下边距加同一个参数 E。
3. 用 LibreOffice 渲染 + `pdftotext` 判断“第 N 页是否仍以预期行结束、下一页是否从预期行开始”，二分查找 E 的最大可行值，再**留约一行余量**（Word 换行可能差一两个字）。
4. 若某页要塞超过 ~1000 twips/边的留白才能填满，说明分页点不对：改为允许相邻行跨页，或调整分页，而不是硬撑。
5. 末页“教学反思”用行高填满，同样二分找上限。
