# 教案美化（蓝金风格）

把一份表格式 Word 教案美化成“看起来是成品”的样子：深蓝横幅页首、分区标题栏、浅蓝灰标签、金色点缀、图标、卡片/编号/标签化排版、必要的图示，每页排满。
本 skill 来自《机械制图》教案3 的完整打磨过程，用户多次修正后的偏好都记录在这里——照着做可以少走一大半弯路。

## 用户的硬性偏好（反复确认过）

1. **保留原表格结构与原文**。只改格式；行列、合并关系尽量不动。确需拆分（例如把单元格里的嵌套评价表改成主表的行、重点/难点做成左文右图）时，按主表**已有网格线**拆，并在回复里说明。
2. **原文不能少**。可以拆条目、改成标签、加小标题，但文字要全在；只修明显笔误（如“府视图→俯视图”），并逐条告诉用户。新增的说明性文字（小标题、占位“待填写”、图注）要说明是新增的。
3. **配色用蓝金**（用户试过 Apple 简洁风，最后选回蓝金）。三层：藏蓝=第一级（页首、分区栏），浅蓝灰+左金边=第二级（大类标签），白底深灰=正文；金色只点缀（编号、短竖条、关键词标签）。详见 `references/style.md`。
4. **不要有“表中表”的缝隙感**：内嵌卡片表必须与外层单元格贴合（外层单元格边距 0、不留空段、卡片表外沿不画线、卡片间一条共用细线、不要三层嵌套）。
5. **页面尽量占满**，页底不留大片空白；但不要为填满而在格子里塞一英寸以上的空白。
6. **表格最左侧边框统一**（所有行首格左边同一条金色细条）。
7. **图示**：原图粗糙可以重画；与新图重复时用新图；图要准确（几何关系、投影规律都要核对），标注不能遮挡，图不能被裁一半。

## 工作流程

1. **准备环境**（沙盒里 LibreOffice 常只有 core，没有 Writer）：
   `apt-get install -y --no-install-recommends libreoffice-writer poppler-utils fonts-noto-cjk`；`pip install lxml pillow defusedxml`。
   图标渲染需要 `npm install @tabler/icons sharp`（仓库 `tools/` 已有 `render_icons.js`）。常用图标已在 `assets/icons/`。
2. **读懂原文件**：解包 → 列出主表每行的单元格（跨列、纵向合并、嵌套表、图片数、文字前缀）→ 渲染原文件看版面。
   注意：用户可能给的是“在上一版基础上改过的文件”（如 v1），要先和上一版逐格对比，找出用户改了什么，**在用户的文件上继续改，不要用自己的旧脚本覆盖掉用户的修改**。
3. **逐区美化**（先做第 1 页给用户确认风格，再推全篇）：
   - 页首：深蓝横幅（尺规类图标 + 眉题 + 大标题 + 副标题）+ 金色细线；作为主表之上的独立小表。
   - 分区标题行：藏蓝底、白字、金色编号 “01 授课信息”。
   - 授课信息：标签格浅蓝灰；空值填浅灰“待填写”；“理实一体”之类做成藏蓝小标签。
   - 内容分析：按意思拆成卡片（课程定位/对接标准/学习内容/数字拓展/课程思政），三排均衡，学习内容三步横排可配缩略图。
   - 学情/目标：大类标签（浅蓝灰+金边+图标，四字竖排两行），小类标签更浅；正文按“；”拆要点、编号用金色数字+悬挂缩进。
   - 重点/难点：只在“教学重点”高亮三等规律之类关键词；可左文右图。方法类：顿号拆成标签。
   - 教学实施：阶段行（金色“第一阶段 | 课前准备”）、表头带图标、课中环节金色序号 01–04、标题分级（▍二级标题 / 金色序号小标题）、编号统一、合并硬换行、拆连写条目、“设计意图”列浅米底区分、窄栏一律左对齐。
   - 教学反思：留白行高填满末页，浅灰“（课后填写）”。
4. **图示**：先列“原图 ↔ 新图”对照表（重复用新、没对应的保留、太粗糙的重画），在对应文字旁插入，嵌入式（不要浮动），带小号灰色图注。画法见 `references/diagrams.md`。
5. **分页与填满**：所有新写文字用“固定值”行距；重要行 `cantSplit`；然后按页二分查找每页的留白参数（见 `references/pitfalls.md` 的“填满页面”）。
6. **自检**：`python3 scripts/check.py 原.docx 新.docx` —— 看文字缺失、结构、页数与总览图；再逐页看渲染图。用 docx skill 的 `validate.py --original` 校验（用户 Word 存过的文件自带的 settings.xml 报错属原有问题，用 `--original` 对比即可）。
7. **交付**：另存新文件名（如 `教案Xv2.docx`，不覆盖用户的版本）→ 提交推送 → 发送预览图与文件 → 在回复里列出：改了什么、新增了哪些文字、修了哪些笔误、结构有何变化、需要用户在 Word 里确认什么。

## 工具

- `scripts/docx_kit.py`：通用函数库（配色常量、run/para/item/h2/h3/chip、单元格边框与底色、嵌入图片/图标/图示、统一左边框、保存）。新教案优先用它写处理脚本。
- `scripts/check.py`：自检（结构、文字完整性、图片数、渲染总览）。
- `scripts/compare_docx.py`：逐行逐格对比两个版本（找用户改动时用）。
- `scripts/reference_jiaoan3/`：教案3 的完整处理脚本（v2.py 页首+第1页、page2_v2.py 第2页、page3.py 第3页起、merge.py 合并图示、polish_v1_to_v2.py 在用户版本上精修教学实施、draw*.py 重画图示、tunelib.py/build.sh 填满页面）。行号与文字是教案3专用的，**只作参考**，照思路改写，不要直接套在别的教案上跑；其中路径指向当时的临时目录，复用时改成本 skill 的 `assets/icons`。
- `references/style.md`：配色、字号、行距、边框、图标清单。
- `references/pitfalls.md`：踩过的坑与原因（强烈建议动手前读一遍）。
- `references/diagrams.md`：图示画法与校核要点。
